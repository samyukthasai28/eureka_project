💡 Architecture Guide: How This Distributed System Works in Practice
1. Why Microservices & Gateway?

Instead of one giant monolith, each domain (Order, Inventory, Payment) is its own independent service with its own isolated database. The API Gateway acts as the secure reverse proxy, handling JWT authentication, circuit breakers, and load balancing.

2. What is Saga Choreography?

Traditional 2-Phase Commit (2PC) locks databases across servers and creates bottlenecks. In Saga Choreography, microservices publish and consume events asynchronously through Kafka using Apache Avro schemas without locking tables.

3. What Happens on Failures?

If payment fails, an InventoryReleaseEvent is dispatched over Kafka. Inventory automatically unlocks and restores the stock, while Order transitions to CANCELLED, guaranteeing eventual consistency!
